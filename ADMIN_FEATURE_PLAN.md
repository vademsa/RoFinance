## Operational extension (2026-10-11)

Scope: minimal account search/pagination, bounded character point/item grants (including canonical Signature IDs), revocation of existing web/mobile sessions, and paginated append-only operation history. No user deletion, password resets, arbitrary configuration/JSON writes, financial inspection or edits.

1. Add separate audit/receipt and revoked-web-session tables. Guard every endpoint with the existing signed session/JWT + pinned ID and fresh stored email; recheck identity inside mutation transactions. Require JSON, exact input keys/options, safe integer bounds, a human reason, same-origin cookie writes and rate limiting.
2. Serialize globally unique request receipts and use the same owner advisory lock as game draws/financial saves. Preserve awards, ranking, equipment and finance; grant only bonus points or canonical inventory IDs/copies. Commit the effect and receipt atomically. Same ID/body is replay-only; altered target/body conflicts.
3. Delete web sessions and create permanent SID tombstones in a single CTE so in-flight resaves cannot restore access. Check tombstones during session hydration (including auth/me), fail closed, revoke mobile sessions/refresh tokens atomically, permit fresh login, and disallow sole-Admin self-revocation.
4. Add account management and history tabs, confirmation dialog, bounded forms, bilingual labels, light/dark contrast and mobile layout. No write on opening/reviewing a form. Retain pending request identity in parent memory through hiding/revalidation, disable leaving/logout, warn on browser unload and replay the exact request if outcome is uncertain. Defer release reloads until reconciliation; do not overwrite the old observed release while pending.
5. Independent worker `/root/audit_admin_operations` iterates scoped source/tests/UI/runtime audits. Run signed cookie/JWT HTTP denials, session resurrection checks, isolated PostgreSQL concurrency/rollback/replay/overflow/projection tests, fresh desktop/phone browser suites, web/mobile TypeScript, logic regressions and staged builds. ## Scope and acceptance (2026-10-11)

The user requested a designed `/admin` page, accessible only to the explicitly named existing account, and repeated independent worker audits until completion. The first dashboard is read-only: system/account/character aggregate counts, backend release health and a searchable paginated canonical cosmetic catalogue. It does not expose anybody's finances, banking information, credentials, sessions, account directory or grant/reset/configuration mutations.

1. Pin the already resolved account UUID in server-only policy and require its fresh canonical database email to match the requested email on every request. Do not assign permission from email claims, display names, roles, headers, query/body parameters, local storage, IP, environment variables or generic administrator flags. Deleting/recreating an account with the same email must not transfer access.
2. Reuse the real signed web-session/mobile-JWT authentication middleware, including revocation checks and invalid-bearer precedence over a valid cookie. Apply authentication and authorization to the entire `/api/admin` namespace and `/admin` page namespace before handlers or static fallback. Missing identity/database failures fail closed. No unauthenticated preflight data/route exception.
3. Proxy protected page requests from the separate web server to the API before serving static/SPA content; the API delivers the existing built shell only after authorization. Use private/no-store caching, authorization/cookie Vary, framing protections and a restricted page CSP. Client code remains a presentation layer, never the authorization boundary.
4. Build a separate lazy-loaded responsive Admin dashboard with an R mark, compact navigation, overview/catalogue views, search/rarity/slot filters, pagination, explicit loading/denied/error states, refresh/logout, bilingual labels and light/dark controls. Keep existing application fonts/styles and 44px controls; no charts or fake metrics are needed. Never mount the finance application or its autosaves on `/admin`.
5. Test the real authentication and owner guard through HTTP: anonymous/other identity, forged claims and request inputs, UUID/email mismatch, deletion/recreation, revoked/malformed JWT, invalid bearer plus valid cookie, path/method variations, unknown endpoints, caching, backend failures and privacy projection. Add proxy regression tests and synthetic browser tests for desktop/mobile, denial, filtering/pagination, late responses/logout, language/theme and viewport widths.
6. One user-requested read-only worker audits the architecture and implementation iteratively. Fix every scoped actionable finding, rerun relevant checks, and obtain a final scoped verdict. This is not a repository-wide or deep security scan and no absolute hack-proof claim is made.
7. Run logic/typecheck/web/mobile build checks, stage and back up binaries, publish web/API/web-server together, restart only required services, and check public/local anonymous denial/readiness plus a fully mocked published dashboard smoke. Do not create production sessions or perform account/financial/game mutations for tests. Mark the GOAL complete only after required evidence is recorded.
